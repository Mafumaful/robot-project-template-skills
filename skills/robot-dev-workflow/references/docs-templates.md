# 文档模板

## 计划 / 排障文档 `docs/<topic>.md`

```markdown
# <主题>

日期：2026-10-15 · 分支：feature/xxx · 状态：讨论稿 / 已确认

## 现象
（时间、运行 ID、截图链接、关键日志行）

## 假设
| 编号 | 假设 | 证据 | 如何验证 |
| H1 | ... | ... | ... |

## 阶段（从零风险到有风险）
### 阶段 1 · 离线（rosbag / 仿真）
通过标准：... 中止条件：...
### 阶段 2 · 真机静止
### 阶段 3 · 有人看护的低速运动

## 约束
- 生产机只读，部署前确认 ...

## 需要你决定的事
| 事项 | 选项 | 建议 |

## 14. 部署到真机（2026-10-14 16:3x 到 16:5x）   ← 结果按日期追加成新小节
```

## 事故记录

- 截图：`docs/<kind>_YYYYMMDD_HHMMSS.png`（如 `crash_20261022_112855.png`、`ba_stop_20261105_142416.png`），正文链接。
- 结构：现象 → 时间线（精确到秒）→ 机理 → 修复（提交、部署时间、备份）→ 局限 / 未验证。
- 数字全部来自日志，写明出处。

## 设计 spec 与实施 plan

- `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`：目标 / 机制 / 组件 / 接口表 / 测试 / 状态行。代码 docstring 引用“spec §N”。
- `docs/superpowers/plans/YYYY-MM-DD-<topic>.md`：头部 Goal / Architecture / Tech Stack；`## Global Constraints`；`## 与 spec 的偏差（实施前已核实）`；每个任务有 `**Files:**`、`- [ ]` 勾选步骤和确切的提交信息。

## 部署记录（放在部署脚本旁边，如 `deploy/<x>/DEPLOYMENT.md`）

1. 什么改了
2. 机器人上的变化（表：文件 / 之前 / 之后 / 哈希）
3. 已验证 · 未验证
4. 只读核对命令
5. 只回滚这一步

## 开发历史 `docs/claude-development-history.md`

每条：北京时间、需求、分支/提交、部署目录、测试范围、未闭环事项。区分“助手报告”与“已核实事实”。合并、推送、部署、硬件验收分开记。

## 组件 README（中文）

部署方法、现场检查、按阶段带日期的变更、接口列表、边界（“不是 / 不会”）、测试数；另配 `VERIFICATION.md`：验证了什么、没有证明什么、截图路径。

## 回顾 / 讲解视频

`docs/video/YYYY-MM-DD-<topic>.mp4`（大文件不入库）+ 入库的 `-notes.md` 脚本：每页一条，粗体一句标题 + 旁白；数字引自日志；小节“现象 / 困难 / 机理 / 结果 / 局限”。
